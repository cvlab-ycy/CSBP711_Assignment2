# 作业二实验设计与评分要求对照

本项目检验 LSNet 的大核感知在小尺寸灰度图像上是否仍有收益。原论文已有 ImageNet 消融，我们不是重复声称“作者没有消融”，而是检验分辨率、数据与训练预算改变后的适用范围。正式结论必须等待全部实验完成。

## 每个操作的理由

| 操作 | 要回答的问题与理由 | 解释边界 |
|---|---|---|
| 使用 Fashion-MNIST | 沿用作业一数据，避免换数据掩盖方法差异；数据规模可支持多组重复与真实消融；服饰类别仍有形状和纹理混淆 | 共同联系是 CV 的学习与评估方法，不声称衣服能代表数字人或人脸 deepfake |
| 单通道 28×28 | 去除颜色这一线索，集中研究结构与空间邻域；训练成本允许更充分检查 | 灰度不是二值；不用 CIFAR-10 不等于证明 RGB 无用 |
| 原始官方 LSNet-T 宽度与深度 | 保留论文核心网络，减少另造一个小网络造成的解释偏差 | 输入通道、分类头、stem 步幅已改变，因此不是原论文设置完全复现 |
| stem 步幅改为 1 | 原始多次下采样会让 28×28 很快缩成极小特征图，使大小邻域的研究失去意义 | 改变了算量与表示，不能对照论文吞吐率直接宣称加速 |
| 官方 SKA 与参考实现核对 | 动态聚合是方法核心；前向和梯度都正确才允许正式训练 | 数值核对不是对科学假设的证明 |
| 保留 7×7 感知并使用小核动态聚合 | 测试论文“大范围产生权重、小范围聚合”的机制 | 不把它误写成普通大卷积接普通小卷积 |
| 去除 LKP 的 depthwise 卷积 | 检验感知阶段的空间卷积是否必要；保留 BN，避免同时去掉归一化 | 不表示移除了全网络空间处理，也不是把所有 LKP 层删除 |
| 把 LKP 从 7×7 改成 3×3 | 区分“需要空间感知”和“确实需要更大的感知范围” | 动态 SKA 与其他结构保持不变 |
| 同一学习率的主要消融 | 降低把调参差异误当成结构收益的风险 | 学习率由 full 的验证结果选择，可能更适合 full；因此公开其他模型的 pilot 敏感性 |
| 固定像素置乱 | 保留像素信息和标签，破坏局部邻域，检查结构收益是否依赖原空间组织 | 影响所有空间模块，不能把全部下降归因于 LKP |
| 复用作业一 split、缩放、seeds | 尽量把新的差异集中到方法与明确声明的训练设置 | 原测试集已在作业一使用，不是全新盲测 |
| 6 次 pilot | 在训练可控的范围内检查两档学习率，并用验证集确定统一设置 | pilot 使用 validation，不使用 test；复用匹配的 seed 42 不算新的独立重复 |
| 3 个种子 | 展示训练随机性，避免单次偶然结果 | 样本仍少，不能用“3/3”代替效应大小和不确定性 |
| 40 epoch 与早停 | 与作业一预算规则对齐，并减少验证损失恶化后的无效训练 | 未证明模型充分收敛 |
| 每个变体追加一次 100 epoch | 检查 40 epoch 或早停是否限制了结论；比较同一长跑内 cap40 与 cap100 的验证选点 | 只有 seed 42；不是复制 ImageNet 的 100 epoch recipe |
| 所有设置冻结后加载 test | 防止本轮用测试分数继续选学习率、checkpoint 或消融 | 不能抹去先前作业一对该测试集的接触 |
| 同一 GPU 重测旧模型延迟 | 避免 GPU、batch、精度差异扭曲速度比较 | 只报告 resident-input 推理，不等于端到端部署耗时 |
| 保存预测、曲线、源码哈希 | 让指标可独立重算，让成员能理解和复现每个决定 | 清晰记录不等于每位成员已实际参与 |
| 单 Slurm 作业顺序执行 | 满足用户要求，避免多个任务争抢资源；所有 GPU 实验与计时在同一分配中完成 | 排队与超时仍受集群状态影响；恢复不会自动创建新作业 |

## 怎样读学习曲线与 pilot

训练 loss 是模型在用于更新参数的 minibatch 上的误差；验证 loss 在不更新参数的 eval 模式下衡量泛化。训练 loss 下降而验证 loss 上升，符合过拟合的表现；两者都高，可能是优化、预算或表示不足。不能只凭 train–validation accuracy gap 确定原因，BatchNorm 模式不同也会影响两者。

pilot 在每次训练中用验证 loss 选 checkpoint，再比较该 checkpoint 的验证 accuracy 来选学习率。这是两个不同的决策。主消融统一使用 full 所选的学习率；其他变体在另一学习率下更好时，需要如实说明优化敏感性，而不能偷偷用测试结果换设置。

正式报告自动写入各变体选中的 epoch、实际停止 epoch、最后 train–validation accuracy 差、两个学习率的验证分数、40→100 epoch 的变化。只有实测数字才能进入结果部分。

## 作业二评分点

| 要求或评分项 | 项目准备的证据 | 仍需人工完成 |
|---|---|---|
| 主论文与支持论文 | CVPR 2025 LSNet；ICLR 2025 pixel transformer；方法与研究问题相关 | 确认论文未被占用和 instructor 的选题登记 |
| Summary 5 分 | 说明 LKP 产生动态权重、SKA 聚合，解释计算动机与证据范围 | 成员必须能用自己的话解释 |
| Critique 7 分 | 指向 Tables 5–7、9；承认已有消融；分析分辨率迁移、训练预算、硬件计时和容量混杂 | 阅读原表并确认每项判断，不用空泛“数据不够”等表述 |
| Reality check 3 分 | 同作业一数据处理和 seeds；官方核心方法的小图适配；结构消融、置乱和预算检查 | 正式结果完成后判断是否支持假设，不预设正结论 |
| Presentation 和 Q&A 8 分 | 计划约 10 分钟讲解加 5 分钟问答；覆盖方法、批判、实测与原因 | 每人发言；排练；准备提问另一组和回答本组局限 |
| Repository、slides、contributions 2 分 | 私有可复现源码、说明、原始证据、幻灯片素材；真实贡献占位 | 文档称 GitHub 可选但 rubric 有相应分值，需确认；遵守不公开要求，不承诺满分 |
| 报告最多 3 页 | 结果完成后压缩为约半页 summary、一页 critique、一页 reality check 加 next steps 和 AI disclosure | Word/PDF 渲染后核对页数和可读性；完整技术汇总不是三页提交稿 |
